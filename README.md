## 📑 File Breakdown: What Goes Where?

### 1. `02_create_tables.sql` (Schema Creation)

This file contains all Data Definition Language (**DDL**) statements. It defines the structure of the database.

* **What goes here:**
* `CREATE TABLE` statements (defining table names, column names, data types).
* Constraints (`PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK`).
* `ALTER TABLE` statements (if modifying existing structures later).


* **Example:**
```sql
CREATE TABLE department(
    department_id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    department_type VARCHAR2(40) NOT NULL UNIQUE, 
    department_location VARCHAR2(30) DEFAULT 'N/A' NOT NULL, 
    department_description VARCHAR2(100)
); 

CREATE TABLE room(
    room_id INT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, 
    facility_type VARCHAR2(50) NOT NULL,
    floor_num INT NOT NULL, 
    equipment VARCHAR2(200), 
    availability CHAR(1) DEFAULT 'Y' NOT NULL CHECK (availability IN ('Y', 'N')), 
    max_occupancy INT NOT NULL
); 

```

### 3. `01_drop_tables.sql` (Table Cleanup)

This script completely wipes the database tables so you can rebuild your schema from scratch.

* **What it contains:**
```sql
-- Drop child/dependent tables first
DROP TABLE orders CASCADE CONSTRAINTS;

-- Drop parent tables next
DROP TABLE customers CASCADE CONSTRAINTS;

```


* **What `CASCADE CONSTRAINTS` does:**
It forces Oracle to drop the table even if other tables reference it using Foreign Keys. It automatically cleans up referential links so script execution doesn't throw dependency errors.
* **⚠️ WHEN TO USE IT:**
* Use this **ONLY** when you want a completely fresh start (e.g., when you significantly change table columns or constraints in `02_create_tables.sql` and need to rebuild the database clean).
* **DO NOT USE IT** if you have added manually generated test data or work in your schema that you do not want to lose. Dropping a table permanently deletes its structure and **all stored data**.

## 🚀 How to Execute Files in Oracle SQL Developer

Follow this step-by-step procedure whenever you open or update files in Oracle SQL Developer:

### Opening Files

1. Open **Oracle SQL Developer**.
2. Go to **File → Open...** (or press `Ctrl + O` / `Cmd + O`).
3. Navigate to your local Git repository folder and select the desired `.sql` file.

### Running Scripts

1. Ensure your university connection (`oracleTMU`) is selected in the **connection drop-down menu** in the top-right corner of the open worksheet.
2. Click the **Run Script** button on the worksheet toolbar (the icon showing a document with a green play triangle) or press **`F5`**.
3. View the **Script Output** panel at the bottom to verify execution logs and confirm there are no syntax errors.

---

## 🔄 Standard Execution Order

When building or resetting your local database environment, execute the files in this precise order:

1. `01_drop_tables.sql` *(Optional: Only run if resetting existing tables)*
2. `02_create_tables.sql` *(Mandatory: Creates table structures)*
3. `03_insert_data.sql` *(Mandatory: Populates test records)*
